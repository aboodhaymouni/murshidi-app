# مُرشِدي — بيانات عامة موثقة وعرض التحكيم 2026

## 1. المشكلة ومعيار النجاح
المشروع نموذج React/Vite/Capacitor ببيانات ثابتة يدعي التحديث والشراكة الرسمية. المطلوب تحويل المعلومات العامة إلى بيانات موثقة قابلة للتحديث، تصحيح دلالات القبول والتكلفة، وتصوير التطبيق الفعلي لعرض Vcoders من 7 دقائق يتضمن Business Model Canvas.

## 2. الأسئلة المحسومة
- المصدر العام فقط؛ المستخدم فوّض اختيار الوسيلة، فلا يلزم حساب خاص.
- تاريخ المراجعة 10 أيلول 2026. لا نسمّي بيانات 2025 بيانات 2026 لمجرد إعادة جلبها.
- آخر حدود تنافسية في صفحة القبول الموحد هي 2025؛ دليل البرامج الحالي 2026/2027 يعالج الأهلية والرسوم بشكل منفصل.
- التحديث عبر HTML العام مسموح ومتاح؛ REST المحظور لا يستخدم. لا يفترض وجود API أو CORS رسمي.
- لا توجد شراكات أو مستخدمون أو إيرادات مثبتة؛ العرض يميز المقترح عن المنجز.

## 3. خريطة السورس ومسار واحد
main.tsx يحمّل LangProvider وHashRouter ثم App.tsx. صفحات Home وROI وCompare وMarket وSimulate وFuture وPersonality تستهلك majors.ts؛ باقي الصفحات تضيف ادعاءات محلية. لا توجد قاعدة بيانات أو طلبات fetch أصلًا. ROI يبدأ بمعدل وميزانية ثم يختار الجامعة الأولى، يتجاهل الميزانية ويحوّل بطالة تخصص مفترضة إلى احتمال عمل شخصي؛ سيستبدل بمقارنة برامج موثقة وسيناريو تكلفة واضح. السورس الأصلي محفوظ خارج المشروع في تسليم_مرشدي/.presentation-build/source-backup-2026-09-10 دون ملفات توقيع.

## 4. البدائل والقرار
| المعيار | وسيط HTML خام | طبقة بيانات موحدة (المختارة) | HTTP أندرويد فقط |
|---|---|---|---|
| التعقيد | منخفض | متوسط بلا قاعدة بيانات | متوسط مع اختبار جهاز |
| المخاطر | تحليل موزع بين الصفحات | رفض النص غير المطابق وحفظ آخر نجاح | اختلاف التطبيق والمتصفح |
| كلفة الانتقال | 7 مستهلكين + نصوص محلية | نفس النطاق مع context واحد | نفس النطاق + native |
| التطور | تكرار لكل مصدر | محول مستقل لكل مصدر | يحتاج حلا إضافيا للويب |
| التوافق | تعديل Vite | Vite + React context موجود النمط | Capacitor موجود |
| الأمان | HTML يصل العميل | نص وأرقام متحققة؛ وجهات ثابتة | وجهات ثابتة لكل جهاز |

نختار طبقة موحدة خلف مسار محلي بنفس الأصل تعمل في dev وpreview، مع لقطة موثقة وبيان حالة الفشل. لا نعلن أن ملف APK المستقل يحدث نفسه ما لم يختبر نقل native أو استضافة فعلية.

## 5. المخاطر
- خلط السكان والخريجين: المؤشر يحمل نطاق السكان والفترة؛ لا يستعمل كاحتمال توظيف فردي.
- تغير HTML أو نقص الصفحات: تحليل كامل الترقيم، تحقق من الأعداد، إبقاء آخر نسخة عند الفشل.
- ادعاء حداثة زائفة: فصل سنة المرجع وتاريخ النشر وآخر تحقق.
- وسيط مفتوح: وجهات HTTPS محددة، تحقق تحويلات، حدود حجم ووقت ودمج الطلبات المتزامنة.
- تاريخ منحة منته: بوابات رسمية وحالة موثقة فقط.
- قص نص عربي: فحص متصفح عربي/إنجليزي وشرائح مرسومة فعليا.

## 6. التنفيذ والتحقق
1. بناء محولات DOS والقبول الموحد ولقطات المصدر؛ اختبار استخراج وتحقق وفشل شبكة وحفظ آخر نجاح.
2. ربط واجهات البيانات بالحالة والمصدر والتحديث الحقيقي؛ تشغيل endpoint ومقارنة بالمصادر.
3. إصلاح ROI/Compare/Simulate: اختيار برنامج حقيقي، تكلفة ساعة منشورة، افتراضات قابلة للتغيير وميزانية مؤثرة، دون ضمان قبول أو دخل.
4. تنظيف جميع الصفحات من الشراكات والقصص والإحصاءات غير المثبتة؛ إصلاح الأزرار التي تعرض خدمات غير موجودة.
5. build وlint واختبارات سلوك وحدود ومدخلات، ثم فحص فعلي للمسارات ومقاسات 375/768/1440 وحالة offline.
6. تصوير الشاشات داخل إطارات هاتف؛ إنتاج PowerPoint وPDF ونص إلقاء 420 ثانية، مراجعة بصرية ومراجعة مستقلة.

## 7. تعريف الاكتمال
التحديث موثق ومجرب؛ الفشل لا يزور تاريخ البيانات؛ لا أرقام رسمية بلا مصدر؛ لا ضمان قبول؛ الميزانية تغير النتيجة؛ الشاشات من النسخة المشغلة؛ العرض يغطي جميع متطلبات اللجنة وBMC ويحمل شعار مُرشِدي واسم Vcoders؛ يتم التصريح بحدود النشر/native إن لم تختبر.
